4. LLM Prompt Engineering & RDF Generation

Formal representation of the prompt engineering techniques applied to extract, model, and bridge the data omissions documented in our SPARQL repository audit.

Update Log: Refined Component Modeling

Change: Transitioned from broad conceptual subject nodes to 9 discrete component entities. This update forces the inference models to map every mythological figure as an independent instance of the class a-cd:CulturalPropertyComponent.

We targeted the documented data gap using three systematic prompt engineering strategies, instructing the foundational models to bypass conversational padding and output data-ready RDF structures directly.

Technique 1: Zero-Shot System Constraints
Isolate the core characters into independent component nodes. Strip out all aesthetic interpretations. Output only valid Turtle syntax using the ArCo framework vocabulary boundaries. Do not include introductory text or chat commentary.
Technique 2: Few-Shot Structural Alignment
[Input] Canvas: Pallas and the Centaur | Component: Centaur -> [Output] ex:Artwork core:hasPart ex:Node_Centaur .
[Input] Canvas: Primavera | Component: Mercury -> [Output] ex:Primavera_Artwork core:hasPart ex:Node_Mercury .
Technique 3: Chain-of-Thought (CoT) Spatial Extraction
1. Evaluate visual boundary limits on a normalized 100x100 grid from right to left.
2. Establish separate URI nodes for overlapping actors. Map metadata fields adhering strictly to approved ArCo prefix documentation constraints.
